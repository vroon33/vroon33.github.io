Does PSNR Lie? study guide

Approximate image-processing hardware, and why one PSNR number cannot tell you whether a cheap circuit is good enough.

Chapter 0

Chapter 1

The problem

Approximate hardware

Image-processing hardware does many additions and multiplications per pixel. Exact arithmetic costs area and power. Approximate computing cuts corners on purpose:

  • drop a few low bits of a number (truncation or rounding);
  • use fewer nonzero digits in a filter coefficient (CSD quantisation);
  • replace an exact adder or multiplier with a cheaper circuit that is sometimes wrong, for example one from the EvoApproxLib library.

The output is then slightly wrong, and the designer has to decide whether the error is acceptable.

How designs are accepted today

The usual check is the PSNR of the approximate output against the exact output. If the PSNR is above a fixed number, often 30 dB, the design is accepted. A survey done for this project found this directly:

  • of 22 approximate-arithmetic papers read in full, 16 report PSNR and 12 report SSIM;
  • 7 state a fixed acceptance threshold, and 4 of those use 30 dB;
  • none compares edge maps with human ground truth, and none compares a pixel metric with a task metric on the same designs.

Why this might be wrong

Definition

An output is field-valued when it is a signal that is used as a signal: a smoothed image, a set of DCT coefficients. A small arithmetic error gives a small output error.

An output is decision-valued when it ends in a decision per pixel: edge or not, corner or not, which region. A small error does nothing unless it pushes a value across the threshold. Then the decision flips completely.

PSNR was made for field-valued outputs. For a decision-valued output, the same PSNR can mean "no harm" or "real harm", depending on where the errors fall. Figure 1.1 shows the idea.

The question

The course project was called Does PSNR Lie? The first idea was that PSNR puts designs in the wrong order for decision-valued operators. The finding that survived every check is about the threshold instead: no single PSNR value tells you that a design is good enough. The value you need depends on the task, on how the circuit is used, and on the images. Chapter 8 tells how the question changed.

The answer in four sentences
  1. For each task, the project measured the safe PSNR: the PSNR above which every design was safe for the task.
  2. It ranges from 29.0 dB (Sobel edges) to 66.3 dB (segmentation), so one fixed threshold cannot fit all tasks.
  3. A 30 dB rule accepts designs that are clearly worse at the task in 4 of 5 tasks, even in the two field-valued control tasks.
  4. For a field-valued task (denoising) the safe PSNR can be predicted by a formula. For decision-valued tasks it cannot, because it depends on the use of the circuit and on the image.
Chapter 2

PSNR, SSIM and the peak

Definition

For an approximate output \(\hat{y}\) and the exact output \(y\) over \(N\) pixels,

\[ \mathrm{MSE} = \frac{1}{N}\sum_{i}\big(\hat{y}_i - y_i\big)^2, \qquad \mathrm{PSNR} = 10\log_{10}\frac{\text{peak}^2}{\mathrm{MSE}}\ \text{dB}. \]

Higher is better. Identical outputs give infinite PSNR.

  • Every 10 dB means the MSE is 10 times smaller.
  • Every 6 dB means the typical error is half as big, because \(20\log_{10}2 \approx 6.02\).
  • In this project PSNR is always measured against the exact design's output on the same input, not against a clean image.

The peak matters

The peak should be the full range the signal can take. For an 8-bit image that is 255. The Sobel magnitude \(M\) goes from 0 to 1530 (Chapter 4), so its peak is 1530. Using 255 for Sobel makes every Sobel PSNR too low by

\[ 20\log_{10}\frac{1530}{255} = 20\log_{10}6 = 15.56\ \text{dB}. \]

This mistake was in the project's own early results. Correcting it moved every Sobel point by the same 15.56 dB, as Figure 2.1 shows.

Note

This is a finding in its own right. A change of peak shifts every PSNR equally, so rankings and Kendall τ stay the same. Any comparison with a fixed number such as 30 dB changes. Papers that quote "30 dB" without saying which peak they used cannot be compared.

SSIM

SSIM (structural similarity) compares local means, contrasts and structure, and is 1 for identical images. The project checked whether SSIM does better than PSNR. It does not. Its Kendall τ with the task change is 0.21 for Sobel and 0.76 for denoising, against 0.25 and 0.80 for PSNR.

Chapter 3

How a design is made cheaper

Each design changes one arithmetic choice in an exact integer datapath. There are four kinds of change.

Axis What it does Error it gives
Truncation of \(k\) bits Drops the \(k\) lowest bits and puts zeros back: (x >> k) << k Always rounds down: a negative bias of about \(-(2^k-1)/2\)
Rounding of \(k\) bits Adds half before dropping: ((x + 2k−1) >> k) << k A bias of about \(+\tfrac12\), the same spread as truncation
CSD to \(N\) digits Rounds each filter coefficient to a number with at most \(N\) nonzero signed digits A fixed change of the filter itself
Library circuit in a slot Replaces every adder or multiplier in one slot with an approximate EvoApproxLib circuit Depends on the data; sometimes large, often biased

Truncation against rounding

Both have the same variance, \((4^k-1)/12\) in units of the input's last bit. They differ only in the mean. That makes them a clean experiment on bias alone.

CSD

Definition

Canonical signed digit (CSD) writes a number with digits −1, 0 and +1, with no two nonzero digits next to each other. Example: \(7 = 8 - 1\) has 2 nonzero digits, where plain binary 111 has 3. Each nonzero digit costs one adder or subtractor in a constant multiplier, so fewer digits means cheaper hardware.

CSD does nothing to Sobel, because its taps 1 and 2 already have one digit each. So the CSD axis is used on the Gaussian, with taps (14, 62, 104, 62, 14), and on the DCT.

EvoApproxLib

EvoApproxLib is a library of approximate adders and multipliers made by evolutionary design (Mrázek et al., DATE 2017). Each circuit comes as a C model and as Verilog. The library reports error metrics (MAE, worst-case error, error probability) measured on uniform random inputs, and it does not report the signed bias. On real image operands these numbers can be very different.

Example

add12u_054 has a mean absolute error of 520.3 on uniform inputs, but 15.9 on the operands that Sobel actually sees. Its bias goes from −6.5 to +15.4. Library numbers do not transfer to images.

Definition

A slot is a group of adders in the datapath that all get the same circuit. In Sobel: u8 (the four first pixel-pair sums), u12 (the "+2·p" sums and the magnitude sum) and s12 (the two signed differences). Harris adds m11, its 11×11-bit multipliers.

Two exact facts about Sobel

M is always even. \(G_x + G_y = 2(p_6+p_8+p_9-p_1-p_2-p_4)\) is even, and \(|a|+|b|\) has the same parity as \(a+b\). So the lowest bit of \(M\) carries no information, and truncating \(M\) by one bit changes nothing.

Truncating M is exactly a threshold shift.

Derivation

Let \(\mathrm{trn}_k(M) = 2^k\lfloor M/2^k \rfloor\). This is a multiple of \(2^k\), so it is at least \(T\) exactly when it is at least the smallest multiple of \(2^k\) that is \(\ge T\):

\[ \mathrm{trn}_k(M) \ge T \iff 2^k\lfloor M/2^k\rfloor \ge \lceil T/2^k\rceil 2^k \iff M \ge \lceil T/2^k\rceil\, 2^k . \]

So a truncated design with threshold \(T\) gives exactly the same edge map as the exact design with threshold \(\lceil T/2^k\rceil 2^k\). If \(2^k\) divides \(T\), nothing changes at all.

Chapter 4

Operators and task metrics

The six operators

Operator What it computes Output Task
Sobel + threshold \(G_x, G_y\) from a 3×3 window, \(M=|G_x|+|G_y|\), edge if \(M\ge T\) Decision Edge detection on BSDS500
Harris Gradients, products \(I_x^2, I_y^2, I_xI_y\), smoothed; \(R=\det-k\,\mathrm{tr}^2\); local maxima Decision Corner repeatability on the Oxford set
Gaussian smoothing 5-tap filter (14, 62, 104, 62, 14)/256 in both directions Field Denoising (control)
8×8 DCT JPEG-style transform with an 8-bit fixed-point matrix Field Compression (control)
Otsu threshold The threshold that best splits the histogram into two classes Decision Part of segmentation
3×3 opening Erosion, then dilation, of a binary map Decision Part of segmentation

The segmentation pipeline is Gaussian → Otsu → opening. It tests the same Gaussian circuits in a second use, this time decision-valued. The Gaussian and the DCT are the controls: field-valued operators where PSNR is expected to work.

The Sobel datapath

With the 3×3 window \(p_1 \dots p_9\) in row order:

\[ \begin{aligned} G_x &= (p_3 + 2p_6 + p_9) - (p_1 + 2p_4 + p_7)\\ G_y &= (p_7 + 2p_8 + p_9) - (p_1 + 2p_2 + p_3)\\ M &= |G_x| + |G_y|, \qquad E = (M \ge T). \end{aligned} \]

\(G_x\) and \(G_y\) each lie in [−1020, 1020], but \(M\) reaches only 1530, not 2040. Both gradients cannot be 1020 at once, because that needs \(p_3\) to be 255 and 0 at the same time.

The task metrics

Task Metric Compared with In simple words
Sobel BSDS boundary F at ODS Human-drawn boundaries How well the edges match what people drew, within a small distance
Sobel (second) Pratt's FOM The exact design's edge map How close the edge pixels are to the exact design's edges
Harris Repeatability within 1.5 px Known homography between two images The share of corners found again in the transformed image
Denoising PSNR against the clean image Clean image (noise σ = 10 added) How well the filter removes noise
Compression BD-rate The original image Extra bits needed for the same quality, in %
Segmentation Relative component-count error The exact pipeline Did the number of regions change?
Definition

Precision is the share of detected edge pixels that match a human edge. Recall is the share of human edge pixels that were detected. \(F = 2PR/(P+R)\).

ODS (optimal dataset scale): one threshold for the whole dataset, chosen to maximise F. OIS: the best threshold for each image separately. The project uses ODS.

  • Re-tuned or fixed threshold. Re-tuned means each design gets its own best threshold. Fixed means every design uses the exact design's best threshold. A design that shifts \(M\) up or down acts like a different threshold, and re-tuning absorbs that. Both are reported.
  • BD-rate (Bjøntegaard delta rate): run the coder at several quality settings, plot bits against PSNR, fit a curve to each design, and measure the average horizontal gap between the curves. +1% means 1% more bits for the same quality. With 10 quality points the project fits a least-squares cubic.
  • Topology changed: the component count or the Euler number (components minus holes) differs from the exact pipeline.
Chapter 5

Deciding that a design is safe

The bootstrap

Definition

A paired bootstrap confidence interval: take the 50 images, draw 50 of them with replacement, and compute the task change of the design against the exact design on that draw. Repeat 10,000 times. The middle 95% of the results is the 95% confidence interval. It is paired because both designs are scored on the same drawn images, so the image-to-image variation cancels.

The margin and the three verdicts

"Is the design exactly as good?" cannot be shown. The question is instead "is it worse by more than a margin δ?". The margins were fixed before any task result was computed:

Task Margin δ
Sobel 0.005 in F
Denoising 0.1 dB of denoising PSNR
Compression 1% BD-rate
Segmentation 0.01 relative component-count error
Harris 0.005 in repeatability, chosen after seeing the data, so Harris is called exploratory

Safe PSNR

Definition

The safe PSNR of a task is the highest PSNR of any design that is not safe (shown inferior or inconclusive). Every design above it is safe. It answers the question: what PSNR threshold would have been needed to accept only safe designs?

Note

Counting inconclusive designs as not safe is conservative on purpose. The paper also reports the version that counts only shown-inferior designs, so the reader can see what this choice does.

Rank agreement

Kendall τ measures how well two orderings agree, from −1 (reversed) to +1 (the same). τb handles ties. Spearman ρ is the correlation of the ranks. A partial ρ is the correlation after removing the effect of a third variable.

Chapter 6

The hardware

Two implementations of the same arithmetic

Definition

Bit-exact: the HLS kernel and the Python reference give exactly the same output bits on the same input. This guarantees that the quality numbers belong to the hardware whose cost is reported. Both sides call the same EvoApproxLib C models.

The numbers to remember

Item Value
Designs 257 = Sobel 105 + Harris 23 + Otsu 13 + opening 1 + Gaussian 85 + DCT 30
Target Zynq-7020 FPGA (xc7z020clg400-1), 10 ns clock (100 MHz)
Tools Vitis HLS 2025.1 and Vivado 2025.1
Checks All 257 pass C simulation and co-simulation bit for bit, and all meet 10 ns after place and route
Throughput One pixel per clock (II = 1). Sobel co-simulation on 512×512 takes 263,180 cycles = 513² + 11
Sobel exact 224 LUT, 331 FF, 1 DSP, 2 BRAM after routing; 10.32 mW dynamic power
Harris exact 1480 LUT, 16 DSP, 22 BRAM; 93.5 mW dynamic power

How the kernels work

All kernels are streaming: pixels arrive one per clock in raster order. A line buffer keeps the last two rows, so a full 3×3 window is available at every pixel without storing the whole image. The loop carries #pragma HLS PIPELINE II=1, so a new pixel enters every clock.

The approximate circuits are plugged in with #ifdef. A generated header may define U8_FN, U12G_FN and so on as an EvoApproxLib C model. If it does not, the code uses plain a + b. So one source file builds every design. The longest kernel is Harris at 181 lines; Sobel has 161 and the others 70 to 83.

Hardware findings

  1. HLS estimates are far off. C synthesis overestimates LUTs about 4× and FFs about 2× (Sobel exact: 884 → 224 LUT, 660 → 331 FF). Only post-route numbers are reported.
  2. Most of a small kernel is not arithmetic. A control kernel with the same streaming and line buffers but no Sobel maths uses 156 LUT. So about 70% of the exact Sobel's 224 LUT is infrastructure.
  3. Approximate adders often cost more on an FPGA. 47 of 78 EvoApproxLib adder swaps cost more LUTs than exact + (Figure 6.2). An FPGA has dedicated carry chains (CARRY4) that make an exact adder cheap. The library circuits are gate-level netlists designed for ASICs, so they are mapped onto general LUTs. Even the library's own exact circuit add12u_19A costs 326 LUT against 224. Synthesising all 168 library circuits alone confirmed it: the library's exact circuits cost 13–88% more LUTs than the HDL operator.
  4. The library's ASIC area still ranks circuits correctly. Spearman 0.73–0.91 with FPGA LUTs. The ranking transfers; the saving against exact + does not.
  5. Approximate multipliers lose to DSP blocks. In Harris, every approximate 11×11 multiplier costs more LUTs (1602–2695) than the exact design (1480 LUT plus DSPs). Only the gradient shift saves area.
  6. The post-route period at a loose clock is not Fmax. At a 10 ns target Vivado stops optimising once timing is met. The directive set alone moves Fmax by 4–12%. Only two designs (G-trn-2, G-trn-3) are established as slower than exact.
  7. HLS can report II = 1 and still fail timing. The first Otsu kernel did, and missed 10 ns after routing (16.6–17.8 ns). Two histogram banks and an unpipelined scan fixed it. Lesson: treat HLS warnings 200-886/887 as errors.
  8. Power from switching activity. Vectorless power estimates guess how often signals toggle. Instead the routed netlist was simulated on real images, its outputs were checked against RTL co-simulation byte for byte, and the switching activity (SAIF) was fed back to Vivado. Static power (about 103 mW) is the same for all designs, so dynamic power is compared.
  9. Vivado is deterministic. Re-implementing the first 13 Sobel designs gave identical results.

Two cost views

HLS decides by itself whether a multiplication uses a DSP block or LUTs. That makes LUT counts hard to compare: the exact DCT uses 62 DSPs and the 1-digit CSD DCT uses none. So for the Gaussian, the DCT and the opening there is also a fabric view, with every multiplier in LUTs. The paper's cost table uses that view for the Gaussian and the DCT. Otsu does not meet 10 ns in the fabric view, so it has only the default view.

Chapter 7

How the experiments ran

Data

  • BSDS500 (Berkeley segmentation dataset): natural photos with human-drawn boundaries. The project uses the 100 validation images. The first 50 (sorted by id) are the main set; the other 50 are the held-out set, added later.
  • Oxford affine set (Mikolajczyk et al.): 8 sequences of one scene under viewpoint, zoom, blur, light and JPEG changes, with known homographies. 40 image pairs, used for Harris.
  • A synthetic set of 96 images with controlled contrast and texture, for the image-dependence check.

The Sobel threshold problem

The proposal said \(T = 60\). On this scale (\(M\) from 0 to 1530), \(T = 60\) marks about half of every image as edge: the median edge density is 49%. People draw boundaries on about 1.5% of pixels per annotator, 5.4% for the union. Densities near the human level need \(T \approx 300\)–500. So \(T = 60\) is meaningless here.

Definition

Density-matched grid. Each design gets 19 thresholds that give the same edge densities as the exact design at \(T = 240, 250, \dots, 420\). A design that inflates \(M\) is then compared at the same edge density, not at the same number.

Grid-edge extension. If a design's best threshold is the first or the last of its 19, the true best may lie outside the grid. Then the next two thresholds that actually change the edge map are added.

The official BSDS benchmark

Matching edge pixels to human boundaries is done with the official BSDS MATLAB code, on a separate cluster that has MATLAB. Two compatibility fixes were needed (a compiler flag and one load call); neither changes the algorithm.

  • The project also wrote a Python port. It differs from the official code by about as much as the official code differs from itself, because the official matcher is randomised.
  • The official matcher, matching a map against itself, scores 0.997, not 1. That is its noise floor.
  • Matching is slow: about 165 s per image for 6 maps at \(T = 60\).

The other tasks

  • Denoising: add Gaussian noise with σ = 10, smooth with the design, compare with the clean image. The exact filter reaches 26.7 dB.
  • Compression: JPEG-style coding with the design's DCT at ten quality factors, BD-rate against the exact DCT. The "exact" DCT is itself 8-bit fixed point: it has a +1.1% DC gain error and caps reconstruction at 47.4 dB. A floating-point DCT is kept as a reference.
  • Segmentation: noise-free images through Gaussian → Otsu → opening; compare the component count and Euler number with the exact pipeline.
  • Harris: repeatability within 1.5 px on the 40 Oxford pairs.
Chapter 8

How the claim changed

A viva often asks what you expected and what happened. This is the order in which it happened.

1. Equal PSNR, different decisions

Two artificial errors on \(M\), both with PSNR 42.11 dB at peak 255: A adds ±2 at random, B subtracts 2 everywhere. Against the exact design's edge map, FOM and recall preferred A on 50 of 50 images at every \(T \le 300\). Against human labels the difference was tiny (F differs by at most 0.004) and its sign depended on \(T\), because B is exactly a threshold shift by 2.

Lesson: always say which reference a metric uses, the exact output or human labels.

2. The Sobel sweep: "PSNR rejects good designs"

105 designs on 50 images, scored by ODS F against human labels, with PSNR at peak 255. The 30 dB rule accepted 44 designs and the task rule 88. Every PSNR-accepted design was fine, so PSNR looked too strict. τ(PSNR, ODS F) was only +0.25, while τ(PSNR, FOM against exact) was +0.82.

3. Harris: "PSNR accepts bad designs"

For Harris, the 30 dB rule accepted all 23 designs, including shift6, which loses 0.027 repeatability. So PSNR looked too lax. Together: "PSNR fails in both directions on decision-valued operators".

4. The controls broke the story

The field-valued controls were added to show that PSNR works where it should. But the 30 dB rule also accepted task-inferior designs there. So false accepts are not special to decision-valued operators. The real problem is that 30 dB is not calibrated for any task. The claim changed from "PSNR ranks badly" to "a fixed PSNR threshold cannot decide acceptance". Rankings by PSNR are in fact reasonable in most tasks (τ 0.76–0.94).

5. The peak mistake

An audit of the paper draft found that Sobel PSNR used peak 255 although \(M\) goes to 1530 (Chapter 2). With the full-scale peak every Sobel PSNR rises by 15.56 dB:

  • the Sobel safe PSNR moves from 13.4 to 29.0 dB;
  • the 30 dB rule's false rejects for Sobel drop from 44 to 6.

So "30 dB rejects 44 good Sobel designs" was an artefact of the convention. At full scale the 30 dB rule is roughly right for Sobel. What survived: the rule accepts shown-inferior designs in 4 of 5 tasks, never in Sobel.

6. Held-out images and the grid edge

Everything except Harris was rerun on the 50 held-out images. Sobel first gave 38.6 dB. The cause was M-rnd-6 (rounding 6 bits, so \(M\) is a multiple of 64): its best threshold was the lowest of its grid, so its F was underestimated. The grid-edge extension (Chapter 7) was applied to both image sets. The held-out Sobel value became 28.9 dB, and the first-set results did not change. The paper says that this rule was added after the held-out run.

Chapter 9

The results

This chapter follows the order of the paper's results section.

An example to start with

The paper opens with one image. Truncating 4 bits in the Gaussian gives 63.9 dB on average (64.8 dB on the image shown). On that image only 42 of 151,209 pixels differ and the Otsu threshold stays the same, yet the number of components drops from 17 to 14. Over the 50 images this design changes the segmentation topology of 44% of them. (151,209 = (481 − 4) × (321 − 4), the valid pixels after the borders.)

Sobel, re-tuned T 100 29.0 27.5 28.9 0 (0) / 6
Sobel, fixed T 100 39.4 29.0 39.3 2 (0) / 2

Denoising 78 44.9 44.1 45.0 13 (12) / 0

Segmentation 78 66.3 60.0 63.9 45 (30) / 0

  • Inferior only is the same as the safe PSNR but counts only shown-inferior designs.
  • False accept: accepted by 30 dB but not safe; in brackets, those shown inferior. False reject: rejected by 30 dB but safe.
  • Sobel reads as: 30 dB is close to right. Every other task: 30 dB is much too low, and segmentation needs about 66 dB.

How robust is it?

  • Counting only shown-inferior designs: 27.5 to 60.0 dB.
  • Doubling every margin lowers the safe PSNR by 3.3 to 8.4 dB; Sobel stays at 29.0.
  • With a fixed Sobel threshold: 39.4 dB, because the threshold can no longer absorb shifts of \(M\).
  • SSIM is no better than PSNR.
  • τ is 0.76–0.94 for Harris, denoising, compression and topology. Sobel against human labels is the exception (0.25), because 74 of 100 designs change F by less than 0.001, and their order is noise.

Predicting the safe PSNR of a field-valued task

Derivation: Eq. 1
  1. The exact denoiser already makes an error against the clean image, with mean square \(\mathrm{MSE}_{dn}\).
  2. The approximation adds its own error against the exact output, \(\mathrm{MSE}_{e}\).
  3. If the two errors are unrelated, their mean squares add: \(\mathrm{MSE}_{total} = \mathrm{MSE}_{dn} + \mathrm{MSE}_{e}\).
  4. So the denoising PSNR drops by \[ \Delta = 10\log_{10}\!\Big(1 + \frac{\mathrm{MSE}_e}{\mathrm{MSE}_{dn}}\Big) = 10\log_{10}\!\big(1 + 10^{(\mathrm{PSNR}_{dn} - \mathrm{PSNR}_e)/10}\big). \] (Both PSNRs use peak 255, so the ratio of MSEs is \(10^{(\mathrm{PSNR}_{dn} - \mathrm{PSNR}_e)/10}\).)
  5. Set \(\Delta = \delta\) and solve for \(\mathrm{PSNR}_e\): \[ \mathrm{PSNR}_{safe} = \mathrm{PSNR}_{dn} - 10\log_{10}\big(10^{\delta/10} - 1\big). \]
Example: do this on the board

\(\mathrm{PSNR}_{dn} = 26.7\) dB and \(\delta = 0.1\) dB.

\[ 10^{0.1/10} = 1.0233,\quad 1.0233 - 1 = 0.0233,\quad 10\log_{10}0.0233 = -16.3, \] \[ \mathrm{PSNR}_{safe} = 26.7 + 16.3 = 43.0\ \text{dB}\quad(\text{measured: } 44.9\ \text{dB}). \]
Why 44.9 and not 43.0?

The measured value is set by one design, u16=add16u_1US. It loses 0.106 dB of denoising PSNR on average (interval −0.130 to −0.085 dB), so it is inconclusive at δ = 0.1. At its PSNR, Eq. 1 predicts a loss of about 0.065 dB. Near the margin the loss changes slowly with PSNR, so this 0.04 dB gap moves the safe PSNR by about 2 dB. Why this one design loses more than predicted was not investigated.

For decision-valued tasks no such formula exists. Their loss depends on where the errors fall relative to the threshold, not on their total energy.

Held-out images

  • Same designs and margins on the other 50 images: 28.9, 45.0, 49.1 and 63.9 dB (against 29.0, 44.9, 48.7 and 66.3). Eq. 1 gives 42.9 dB.
  • 30 dB again accepts shown-inferior designs: 10 for denoising, 11 for compression, 30 for segmentation, none for Sobel.
  • Transfer across images: use the safe PSNR from the first 50 images as the threshold on the other 50. It accepts at most 2 not-safe designs per task, none shown inferior. The 30 dB rule accepts 13 to 39. The calibrated threshold is conservative for Sobel and segmentation: it rejects 4 and 10 safe designs.
  • Transfer across design families is worse. The 16 quantised Gaussian designs give 30.6 dB, because no quantised design lies between 30.6 and 51.2 dB. That threshold accepts 12 library circuits that are not safe. A threshold calibrated on one kind of approximation does not carry over to another.

The same circuit in two uses

52 Gaussian circuits are safe for denoising. 32 of them are not safe as the front end of segmentation, at PSNRs of 46.2–66.3 dB. The reverse never happens. On the held-out images it is 26 of 52.

Why: in denoising the error is spread over all pixels and costs PSNR in proportion. In segmentation, only errors that push a pixel across the Otsu threshold matter, and one gray level can split or merge regions. A PSNR check on the front end also cannot see approximations in later stages: an Otsu design with a 16-bit shorter comparison word has a mean relative component-count error of 4.6, while the front-end PSNR is unaffected.

Which images are fragile

Definition

The fragility of an image is the share of Gaussian front ends above 50 dB that change its topology.

  • Spearman ρ = 0.60 (p = 4×10⁻⁶); partial ρ = 0.45 after removing the component count. Held-out: 0.78, partial 0.67. Synthetic set: 0.78, partial 0.68.
  • Contrast alone predicts fragility only weakly (−0.29).
  • The 63.9 dB design changes 44% of images, so a check on one random image passes it with probability 0.56. Validating on one image is a coin toss.

Choosing a design by cost

  • Cost is post-route LUTs. For each rule, take the cheapest design it accepts.
  • For Harris, the Gaussian (both uses) and the DCT, the cheapest design above 30 dB is task-inferior: −0.027 repeatability, −1.44 dB denoising, 9.5% component-count error and −4.7 dB BD-PSNR.
  • The task rule saves less area and loses nothing beyond its margin.
  • For Sobel the two picks differ by one LUT (209 for add8u_8LL, 208 for add8u_8AS).
  • The largest saving found is 57% of the LUTs, from 1-digit CSD in the DCT, but it fails both rules.
Chapter 10

Objectives and recommendations

The five course objectives

1. Same ranking?

Mostly yes against the exact output: τ 0.76–0.94, and 0.82 for Sobel FOM. Against human labels Sobel's τ is 0.25, because most designs barely change F. The problem is the threshold, not the ranking.

2. Is the PSNR pick on the front?

For Harris, the Gaussian and the DCT, the cheapest design passing 30 dB is task-inferior. For Sobel at full-scale peak the two picks differ by one LUT.

3. Which mechanism?

Library adders in the wide u12 slot: large, data-dependent, heavy-tailed, biased errors (bias −97 to +528, 99th-percentile error up to 1,619). Truncation and rounding give small, regular errors that PSNR orders well.

4. Image statistics?

Yes. The share of pixels within one gray level of the threshold predicts fragility (ρ 0.60, held-out 0.78, synthetic 0.78).

Objective 5 asked for a protocol. It is the three recommendations below.

Three recommendations

  1. Accept on the task metric of the actual use, with a margin fixed in advance and a paired bootstrap over tens of images. If a PSNR threshold is needed, compute it with Eq. 1 for field tasks, and calibrate it per operator, use and design family for decision tasks.
  2. State the PSNR convention (the peak) and the reference of every metric.
  3. Describe test images by their near-threshold pixel share, and never validate on one image.

Deliverables

A Python harness with a bit-accurate approximation layer, a results database and figures, a survey of 25 papers, and HLS sources with Vivado reports for 257 designs. The plan asked for 8 to 12.

Chapter 12

Questions to practise

Answer out loud first, then open the answer. The numbers come from the project. The wording is a suggestion: put it in your own words.

The idea

  • What is the difference between field-valued and decision-valued outputs?A field-valued output is a signal used as a signal, like a smoothed image: a small error gives a small change. A decision-valued output is a yes/no or a label per pixel: a small error does nothing unless it crosses the threshold, and then the decision flips completely.
  • So does PSNR lie?Not in ranking: it orders designs roughly right for most tasks. It misleads when one fixed number is used to accept designs. The number needed ranges from 29 to 66 dB depending on the task, and it changes with the use of the circuit and with the images.
  • Why include field-valued controls?To check that any failure is specific to decision-valued tasks. It was not: 30 dB also accepted bad designs for denoising and compression. That changed the claim to "the threshold is uncalibrated", and gave the contrast that the field-valued threshold can be computed (Eq. 1) while the decision-valued one cannot.

Method

  • What exactly is "safe"?The 95% bootstrap interval of the design's task change lies entirely above −δ: with 95% confidence the design loses less than the margin.
  • Why a bootstrap and not a t-test?The task metrics (F at ODS, BD-rate, count errors) are not normally distributed, and some are dataset-level numbers: ODS F needs the whole set. A bootstrap over images works for any statistic and is paired.
  • Why fix the margins before the data?Otherwise the margins can be chosen to make the result look good. For Harris that was not done, so Harris is called exploratory.
  • Why the full-scale peak?PSNR compares the error with the range the signal can take. Sobel's magnitude reaches 1530. Using 255 understates its PSNR by 15.56 dB. The ranking does not change, but every threshold comparison does.
  • Why re-tune the threshold per design?In practice the designer sets T for their own hardware. A design that adds a bias to M behaves like a different threshold, and re-tuning removes that. The fixed-threshold result is reported too.
  • Why match edge densities instead of using the same T values?A biased design shifts M, so the same T gives a different edge density. Matching densities compares designs at the same operating point.
  • Why 50 images? Is that enough?It gives intervals narrow enough to classify most designs, and BSDS matching is expensive (about 165 s per image for 6 maps, and every design needs 19 thresholds on every image). Everything was then repeated on 50 more images with the same picture.
  • How is the Harris response computed in the hardware?Gradients as in Sobel, then the products \(A = I_x^2\), \(B = I_y^2\), \(C = I_xI_y\), smoothed with a [1 2 1] binomial, then \(R = 2^{KK}(\det - k\,\mathrm{tr}^2)\) with \(k = KN/2^{KK}\) as integers, then 3×3 non-maximum suppression.
  • Why is the segmentation PSNR measured on the Gaussian output?The question is whether a designer who checks the Gaussian with PSNR would accept the circuit for segmentation. The PSNR is of the circuit's own output; the task is downstream.

Results

  • Explain Eq. 1.Unrelated errors add in mean square. The denoising loss is \(10\log_{10}(1 + \mathrm{MSE}_e/\mathrm{MSE}_{dn})\). Set it to δ and solve for the PSNR of the approximation. With 26.7 dB and δ = 0.1 dB this gives 43.0 dB.
  • Why is the Sobel safe PSNR so low compared with segmentation?Re-tuning the threshold absorbs much of Sobel's error (truncating M is exactly a threshold shift), and F against human labels is insensitive: 74 of 100 designs change it by less than 0.001. Segmentation counts regions, and one flipped pixel can split a region, so it needs a very high PSNR.
  • What does "accepted with probability 0.56 on a single image" mean?The 63.9 dB design changes the topology of 44% of the images. Test it on one random image and 56% of the time you see no change and accept it.
  • Why does near-threshold mass predict fragility?A one-level error can only flip pixels within one level of the threshold. Images with many such pixels have more pixels that can flip.
  • Why does a calibrated threshold not transfer across design families?Each family has its own error shape. The quantised Gaussians jump from 30.6 to 51.2 dB with nothing in between, so the threshold they give (30.6 dB) is far too low for library circuits, whose errors at the same PSNR do more harm.

Hardware

  • What does bit-exact mean, and how was it checked?The HLS kernel and the Python reference give exactly the same output bits on the same input. Golden vectors from Python were compared in C simulation and in RTL co-simulation, for all 257 designs.
  • Why do approximate adders not save area on an FPGA?The FPGA's carry chains make exact addition very cheap. The library circuits are gate-level ASIC designs mapped onto general LUTs. 47 of 78 swaps cost more LUTs than exact.
  • What is II = 1?An initiation interval of 1: the pipeline accepts a new pixel every clock cycle.
  • Why not trust the HLS report?C synthesis overestimated LUTs about 4×, and once reported II = 1 for an Otsu design that failed timing after place and route. Only post-route numbers are reported.
  • How was power measured?The routed netlist was simulated on real images, its outputs checked against RTL co-simulation, and the switching activity saved as SAIF and given to Vivado's power analysis. Only dynamic power is compared, because static power is the same for all designs.
  • Why is the Sobel saving so small (about 7%)?About 70% of the Sobel kernel's LUTs are streaming infrastructure (line buffers, window, control), which approximation does not touch.

The process

  • What was the biggest mistake found in the project's own work?The Sobel PSNR peak. It turned a headline ("30 dB rejects 44 good Sobel designs") into an artefact. It was corrected, and the result that survived is that 30 dB accepts shown-inferior designs in 4 of 5 tasks.
